Problem A3: Monte Carlo Simulation - Estimating Pi#

One of the most powerful applications of loops and random numbers is Monte Carlo simulation – a computational technique used by engineers to solve problems through random sampling.

Background: The Dart Board Method#

Imagine throwing darts randomly at a 1x1 square with a quarter-circle (radius = 1) in the corner:

  • Square area = 1

  • Quarter-circle area = π/4

  • Probability dart lands in quarter-circle = π/4

Therefore: π ≈ 4 x (darts in quarter-circle) / (total darts)

A point (x, y) is inside the quarter-circle if: x² + y² ≤ 1

Part A3.1: Single Point Test#

Write a program that:

  1. Imports random and math modules

  3. Generates a random point (x, y) with random.random() (values 0 to 1)

  4. Calculates distance: math.sqrt(x**2 + y**2)

  5. Checks if inside the quarter-circle (distance ≤ 1)

  6. Prints: coordinates (3 decimals), distance, and whether it’s inside

Problem B2.4: Can You Guess My Seed?#

The instructors have secretly set a random seed, and run the following code:

import random
random.seed(SECRET)  # my secret seed
numbers = [random.randint(1, 10) for _ in range(5)]
print(numbers)

Suppose I show you the output:

[4, 3, 3, 4, 7]

Your job is to guess my seed.

Instructions

  • Write a Python program that tries every possible integer seed from 1 to 200.

  • For each seed, generate the same number of random values and compare them to the sequence I gave you.

  • When you find a match, you’ve found my seed!

🚩 Common mistake: getting the range bound wrong in an exhaustive search. “Every possible integer seed from 1 to 200” means range(1, 201) – range(1, 200) silently skips checking 200 itself. This is the same exclusive-upper-bound rule as any other range(), but easy to miss when the number in the problem statement and the number you type don’t visually match.

Problem B2.6: Order Dependence in Randomness#

You know that setting a seed makes random numbers reproducible. But reproducibility depends not only on the seed – it also depends on the order of random calls. Even small changes in control flow (loops, conditionals) can completely change the output sequence.

Instructions

  1. Import the random module and set the seed with random.seed(123).

  2. Run both Snippet A and Snippet B below and compare the outputs.

Snippet A

import random
random.seed(123)

for i in range(3):
    x = random.randint(1, 10)
    if x % 2 == 0:
        y = random.random()
        print(f"Loop {i+1}: x={x}, y={y:.3f}")
    else:
        print(f"Loop {i+1}: x={x}")

Snippet B

import random
random.seed(123)

for i in range(3):
    x = random.randint(1, 10)
    y = random.random()
    if x % 2 == 0:
        print(f"Loop {i+1}: x={x}, y={y:.3f}")
    else:
        print(f"Loop {i+1}: x={x}")

Questions

  • Do Snippet A and Snippet B produce identical outputs? Why or why not?

  • How does the placement of random.random() affect the sequence of random values consumed?

  • If two students use the same seed but structure their code differently (e.g., conditionals or loop order), will they get the same results?

  • What does this teach you about reproducibility in scientific code?

🚩 Common mistake: assuming the same seed always produces the same visible output regardless of code structure. The seed fixes the underlying sequence of values random will hand out, in order – but which calls in your code actually consume values from that sequence, and in what order, depends entirely on your program’s control flow.

See the reading’s Pseudo-Random Numbers in Python section for how the underlying sequence actually works.
